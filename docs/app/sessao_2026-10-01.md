## 2. Como reconstruir em outra máquina (v2)

```
pip install -r app/requirements.txt            # + poppler-utils (pdftotext) se for reimportar o PDF
python3 scripts/app_cifra_lista.py decifrar data/eleitores/eleitores_v2.csv.enc --senha "<senha da equipe>"
python3 scripts/app_construir.py --lista data/eleitores/eleitores_v2.csv.enc --grava --senha-equipe "<senha da equipe>"
bash scripts/app_publicar.sh --subpasta v2     # publica em gh-pages/v2/
python3 -m pytest -q app/testes                # 15 testes
APP_SENHA_EQUIPE="teste amostra" python3 scripts/app_construir.py --grava && NODE_PATH=/opt/node22/lib/node_modules node app/testes/ponta_a_ponta.mjs   # 16 verificações
```

- A **senha da equipe** foi sorteada pelo build em 01/10 e entregue no chat; **não está em lugar
  nenhum do git**. Guarde-a fora do repositório. É a mesma senha que cifra `eleitores_v2.csv.enc`
  e o pacote `equipe.enc` publicado. Trocar a senha = recifrar a lista + reconstruir + republicar.
- O PDF original do TRE (`Lista de eleitores_Dublin.pdf`, 29/09) fica só na máquina de quem
  constrói; **não volta ao git**. O `.enc` substitui a necessidade dele para o build.
- Build da lista real leva ~4 min (33 mil hashes PBKDF2 em paralelo).

## 5. Purga de dados pessoais do histórico (01/10)

Três PDFs com lista nominal (`appeleicoes` 29–30/09, `DUBLIN.pdf` em `main`) e dois PDFs de
mesários com título (`conferencia/MRV - DUBLIN.pdf`, `APOIO LOGÍSTICO - DUBLIN.pdf`) foram
removidos de **todos** os commits de **todos** os branches do remoto (`main`, `appeleicoes`,
`appeleicoes2` e mais 14 branches antigos), com force-push. Consequências:

- Qualquer clone local precisa de `git fetch --prune` e `git reset --hard origin/<branch>` antes
  de trabalhar, senão o próximo push reintroduz os commits velhos.
- Os commits órfãos continuam acessíveis por SHA até o GitHub limpar o cache. O texto do pedido
  ao suporte ("Remove sensitive data"), com todos os SHAs, foi gerado na sessão de 01/10
  (`pedido_suporte_github.md`, no rascunho da sessão); se perdido, os SHAs antigos estão nos
  reflogs do GitHub e podem ser recuperados pelo suporte a partir das datas.
- `docs/TRANSFERENCIA_REALIZADA.md` ainda cita os dois PDFs de mesários por nome (registro
  histórico, sem dados).
